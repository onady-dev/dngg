# 쿼터 태깅 + 팀파울 표시 설계

- 날짜: 2026-07-18
- 상태: 승인됨
- 범위: 게임 기록에 쿼터 태깅(최소 범위) + 선수 파울 자동 합산 기반 팀파울 표시

## 배경 / 목표

현재 Game에는 쿼터 개념이 없고, 점수·파울은 프론트가 Log 목록을 순회해 계산한다
(파울은 `logitem.name === "파울"` 문자열 매칭). 팀파울은 농구 규칙상 "쿼터별 팀 파울
누적"이므로 쿼터 태깅이 전제조건이다.

목표:

1. 모든 신규 로그에 발생 쿼터를 저장한다.
2. 기록 화면에 현재 쿼터 표시·전환 UI를 제공한다.
3. 현재 쿼터의 팀별 파울 합산(팀파울)을 기록 화면에 표시한다.

비범위(YAGNI): 쿼터별 점수 박스스코어, 보너스(자유투) 상황 강조, 선수 없는 팀 단위
파울 이벤트, 그룹별 쿼터 수 설정.

## 선택한 접근: Game.currentQuarter + 서버 쿼터 스탬프

"현재 쿼터"는 서버(`Game.currentQuarter`)가 단일 진실이다. 로그 생성 시 서버가
게임의 현재 쿼터를 로그에 찍는다. 클라이언트는 쿼터 값을 전송하지 않는다.

대안 비교:

- 프론트 로컬 상태로만 관리: 새로고침 시 1쿼터로 리셋되어 오태깅, 다중 기록자 간
  불일치 → 기각.
- "쿼터 종료"를 로그 이벤트로 기록해 리플레이로 도출: undo와 자연 통합되지만
  `Log.playerId` 필수 제약과 그룹별 Logitem 시딩 필요, 모든 조회 코드가 리플레이를
  알아야 함 → 최소 범위 대비 과설계로 기각.

## 1. 데이터 모델 (backend/src/entities/)

- `Game.currentQuarter`: `int`, `default: 1`. 기존 게임 행은 자동으로 1이 채워진다
  (`synchronize: true`가 컬럼 추가를 반영 — 기본값 있는 컬럼 추가는 안전한 방향).
- `Log.quarter`: `int`, `nullable: true`. 신규 로그는 항상 서버가 값을 채우고,
  기존 로그는 `null`로 남긴다 — 조회 측에서 `null`은 1쿼터로 간주한다.
  (백필 없음: 과거 경기는 실제 쿼터를 알 수 없으므로 데이터를 조작하지 않는다.)

## 2. 백엔드 API

### PATCH /game/:id/quarter

- JWT 가드. 기존 `PATCH /game/:id`(status)와 동일하게 요청자 소속 그룹의 게임인지
  검증(`findOwnedGame` 패턴).
- Body: `{ quarter: number }` — DTO 검증 `@IsInt() @Min(1) @Max(10)`
  (4쿼터 + 연장 여유분).
- `FINISHED`/`DELETED` 게임은 400 거부.
- 응답: 갱신된 게임.

### LogService.createLog 수정

- 게임 소유 검증 시 이미 게임을 조회하므로(`findOwnedGame`), 그 게임의
  `currentQuarter`를 로그의 `quarter`에 스탬프한다.
- `PostLogRequestDto` 변경 없음 → 전역 `forbidNonWhitelisted`와 충돌 없음.

### redoLog

- 원본 로그의 `quarter`를 그대로 복사한다 (현재 쿼터가 아니라 원래 발생 쿼터 유지).

## 3. 프론트엔드 — 기록 화면 (frontend/src/app/record/[id]/page.tsx)

- 점수 표시 아래 쿼터 표시줄: `1Q 2Q 3Q 4Q` 칩 + 현재 쿼터 강조.
  - `canRecord`일 때만 칩 탭으로 쿼터 전환(이전 쿼터로 되돌리기 포함 — 실수 대비).
  - 4Q 이후에는 `연장(5Q)` 버튼 노출 (전환할수록 6Q, 7Q… 최대 10).
  - 전환 시 `PATCH /game/:id/quarter` 호출 후 로컬 `game.currentQuarter` 갱신.
- 팀파울 표시: 각 팀 헤더 옆 `팀파울 n` 배지.
  - 기존 `foulCount` useEffect에서 함께 계산: `logitem.name === "파울"`(기존 관례
    유지) && `(log.quarter ?? 1) === game.currentQuarter`인 로그를 홈/어웨이
    소속으로 분류해 카운트.
  - 쿼터가 바뀌면 자연히 0부터 다시 시작한다.
- 로그 히스토리 항목에 `2Q` 같은 쿼터 라벨을 소형 표시.
- 타입: `frontend/src/types/game.ts`의 `Game`에 `currentQuarter`, `Log`에
  `quarter` 추가.

## 4. 에러·경계 케이스

- 다중 기록자: 쿼터는 서버 단일 진실 — A기기가 2Q로 넘기면 B기기의 다음 기록도
  2Q로 저장된다. B 화면의 쿼터 표시는 다음 재조회 전까지 구값일 수 있으나, 현재
  화면도 실시간 동기화가 없는 구조라 동일 수준으로 수용한다. 로그 저장 응답에
  `quarter`가 포함되므로 그 시점에 표시를 보정한다.
- 되돌리기(undo): 로그만 삭제하며 쿼터는 건드리지 않는다. 쿼터 전환의 취소는 칩
  탭으로 이전 쿼터를 재선택하는 것으로 갈음한다.
- 조회 전용 사용자(비로그인/타 그룹): 쿼터 표시만 보이고 전환 불가.
- 종료된 게임: 쿼터 전환 API가 400을 반환하고, UI도 전환을 막는다.

## 5. 테스트

- 백엔드:
  - `log.service` — createLog가 게임의 `currentQuarter`를 스탬프하는지,
    redoLog가 원본 `quarter`를 유지하는지.
  - `game.service` — 쿼터 전환 성공 / 범위 밖(0, 11) 거부 / `FINISHED` 거부 /
    타 그룹 거부.
- 프론트: 기존에 컴포넌트 테스트가 없는 구조이므로 수동 스모크로 갈음
  (기록 → 쿼터 전환 → 기록 → 팀파울 카운트가 쿼터별로 리셋되는지 확인).
